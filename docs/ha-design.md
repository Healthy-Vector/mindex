# HA(무중단) 설계 문서 — ECR-001

**담당 P1 · RFP 2.3 근거 · 1차 서면평가 제출용**

본 문서는 실제 3노드 클러스터를 구성·실증하는 대신, **설계 문서 4종 제출로 이행**한다는 RFP 2.3의 결정에 따른 산출물이다.

## 1. 왜 실증하지 않는가 (미실증 사유서)

| 항목 | 내용 |
|---|---|
| 보유 라이선스 | Enterprise (trial), **서버 1대**, 특정 호스트에 바인딩 |
| 구조적 제약 | 노드가 1개면 승격시킬 Standby가 없어 Failover 자체가 성립하지 않음 |
| 과제 공고문 인용 | *"새로운 리더를 자동 선출하여 하나의 노드만 Primary 역할을 수행하도록 강제"* — 서버가 1대면 이 문장 자체가 성립하지 않음 |
| 대응 방침 | 인프라 기준선을 단일노드안으로 확정(RFP 2.3). 라이선스 추가 확보 시 CR-01로 상향, 이때 아래 설계를 그대로 실증에 사용 |
| 대체 실증 | 백업·PITR 복구(ECR-003·TER-005)를 실제로 구현·측정하여 "설계는 했고, 복구 실증으로 대체했다"를 증명 |

이 사유서는 라이선스 문의 메일 회신을 근거로 첨부한다 (회신 도착 시 갱신).

## 2. 구성도

목표 아키텍처 (CR-01 발동 시 실제로 구축할 대상):
┌─────────────┐
                │  OpenProxy   │  ← 앱은 이 하나의 엔드포인트만 바라봄
                │ (커넥션 라우팅) │
                └──────┬──────┘
                       │
          ┌────────────┼────────────┐
          │            │            │
    ┌─────▼────┐ ┌─────▼────┐ ┌─────▼────┐
    │  Node 1   │ │  Node 2   │ │  Node 3   │
    │ (Primary) │ │ (Standby) │ │ (Standby) │
    └─────┬────┘ └─────┬────┘ └─────┬────┘
          │            │            │
          └────────────┼────────────┘
                       │
                ┌──────▼──────┐
                │    etcd      │  ← 클러스터 상태 공유, 리더 선출
                │  (Patroni)   │
                └─────────────┘
- 장애 감지: 각 노드가 etcd에 상태를 주기적으로 기록, Patroni가 감시
- 장애 시: Primary 응답 없음 감지 → etcd 합의로 새 리더 선출 → Standby 중 1개가 Primary로 승격 → OpenProxy가 새 Primary로 라우팅 전환
- 지금(단일노드안)은 이 중 **Node 1만 존재**하는 상태. Node 2·3, etcd 클러스터는 CR-01 발동 시 추가
