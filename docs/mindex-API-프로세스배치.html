P4

별도 호출 없음. ④ 응답에 상대 계약·겹친 기간·근거가 이미 들어 있음

⑥

확정 저장

P4

성공이든 충돌이든 항상 커밋. staging 정리까지 같은 트랜잭션

④ 검증과 ⑥ 확정 저장은 같은 EXCLUDE 제약을 씁니다. 검증은 결과만 보고 되돌리고, 저장은 실패했을 때만 되돌린 뒤 conflicted 로 기록합니다. 판정 로직이 두 벌이 되지 않습니다.

버전 · 최종 계약 등록

상세 화면의 두 버튼. 새 API가 아니라 ① 로 되돌아갑니다

이 둘은 순서가 있는 흐름이 아니라 계약 상세 화면에서 갈라져 나가는 동작입니다. 버전·최종 계약 등록은 새 엔드포인트가 아니라 등록 흐름 ① 로 되돌아가는 진입점입니다.

IP 관리 흐름 UI-D-001 · UI-D-002 · 계약과 독립된 마스터 데이터

㉮

목록 조회 · 검색

UI-D-001 좌측 목록. 비활성 IP 토글로 숨김

㉯

상세 · 수정 · 활성화

행 클릭 시 우측 패널. 수정 버튼은 UI-D-002 를 수정 모드로 염

㉰

신규 등록

경로 1/2 직접 진입(UI-D-002) · 경로 2/2 업로드 중 신규 등록

삭제 기능은 없습니다. 이미 등록된 계약이 그 IP를 참조하고 있어 비활성화로 대신합니다. 활성 스위치는 확인 없이 즉시 반영되며, 삭제가 아니므로 되돌리기 쉽습니다.
신규 등록 경로는 둘입니다 — ㉰ 직접 진입(IP 관리 화면)과 업로드 중 신규 등록(③ 단계의 13번 호출). 같은 엔드포인트를 씁니다.
OST·리메이크는 별도 IP 로 등록하고 ip_relation 으로 원작과 잇습니다. 시즌·에피소드 같은 작품 내부 범위만 content_asset 이 담당합니다.
